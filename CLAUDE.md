# CLAUDE.md — nis2-pulse

Open-source (AGPL-3.0) Go CLI for external network-surface and cryptographic-hygiene evidence collection under the EU NIS2 Directive (2022/2555) and Portugal's Decreto-Lei 125/2025.

## Rules

1. **TDD & quality gates:** write tests first. A change is complete only when `go test -v -race ./...` passes and `golangci-lint run` reports 0 issues.
2. **Safety model is a feature:** active checks must never run without `--active`; the engine enforces this and it is covered by tests. Never add port scanning, vulnerability probing, or exploitation.
3. **No secrets, no real client data** in code, tests, fixtures, or commits. Use synthetic fixtures, local test servers, or public test services (`dnssec-failed.org`, `badssl.com`).
4. **Wording:** reports say "evidence related to", never "compliant" or a global compliance percentage.

## Commands

```bash
make test          # go test -v -race ./...
make lint          # golangci-lint run
make build         # static binary in bin/
make check-sources # verify RFC quotes and sections against RFC texts
```

## Design notes

- `Check` interface with `Tier` (Passive/Active) and injected `Deps` (resolver, HTTP client, clock) so unit tests never touch the network.
- **Active checks:** use only `d.HTTP` (built by the CLI with `safehttp.New`) for HTTP and `d.Dial` (see below) for raw TCP. Never create an `http.Client`, `net.Dial`, or `tls.Dial` inside a check, never set `InsecureSkipVerify`, never follow redirects. Connect only when the domain publishes the record the check is about (see `MTASTSPolicy`), and make one request. Every new active check needs tests proving: it does not run without `--active`, it does not connect without the published record, and certificate errors become findings. Test servers use a throwaway CA (`mtasts_helpers_test.go`), never skipped verification.
- **Raw TCP** (TLS probing, STARTTLS) goes only through `d.Dial`, built from `safenet`. The TLS probe sends `ClientHello` messages and nothing else: no completed handshake, no application data. Its oracle in tests is a real Go TLS server configured with exact versions and suites; the catalog (`ciphers_gen.go`) is generated from the IANA CSV by `tools/genciphers`, never typed by hand.
- **SMTP** (`internal/smtpprobe`, used by the STARTTLS check) speaks `EHLO`, `STARTTLS`, and `QUIT` only. Never add `MAIL`/`RCPT`/`DATA`/`VRFY`/`EXPN`/`AUTH` (a test fails if they appear). Replies are read one byte at a time: do not wrap the connection in a `bufio.Reader`, as it would swallow bytes belonging to the TLS handshake. Fake servers in tests do a real `STARTTLS` upgrade. Certificates in those tests are issued relative to the signed DNS world's clock (`stNow`), never `time.Now()`, so tests do not rot when fake signatures expire.
- **DANE:** a TLSA record counts only if DNSSEC authenticates it (`dnssec.Validator.ValidateRRset`); in an unsigned zone senders ignore it, and with a broken signature they hold mail back. `DANE-EE` ignores names and dates; `DANE-TA` needs a linked chain and the host name (RFC 7672 §3.1).
- **`--timeout`** defaults to `0`: each check gets `engine.DefaultCheckTimeout` or the longer time it asks for through `engine.Timeouter`. A positive `--timeout` overrides every check.
- **Cross-checking against external tools:** `dig`/`openssl` use the system resolver, while `nis2-pulse` uses `--resolver`. With split-horizon DNS they can reach different servers; pin external tools to the same IP (`openssl s_client -connect IP:443 -servername NAME`). Compare in both directions and exhaustively (every suite the tool knows), not a sample: omitting an accepted suite is the worst error of an enumerator.
- **Exact counts in commit messages:** count mutations and findings directly from code and test output rather than estimating.
- **Never share a `dns.Client` between goroutines.** `Client.Exchange` clears the client's in-flight ID map on return, so overlapping queries fail with `ID mismatch`. `dnsx.Client` therefore uses the stateless package-level `dns.Exchange`. Regression test: `TestResolverIsSafeForConcurrentUse` (`-tags=integration`).
- **DNSSEC attribution rule:** a failure may only be a verdict on the audited domain (`bogus`) when it happens at the TLD or below. Root problems (stale anchors after a KSK rollover, a resolver that strips RRSIGs), query errors, and unsupported algorithms are `indeterminate` → `unknown` finding. All DNSSEC queries use the CD bit (`QueryCD`), asserted by a test.
- `RRSIG.Verify` in `miekg/dns` v2 requires a non-nil `*SignOption`, does **not** check the validity period (call `ValidPeriod`), and sorts/mutates the RRs and RRSIG in place (always clone first, as `tryVerify` does).
- **Mutation-testing security logic:** break the code on purpose (restore cleanly afterwards) and confirm the right test fails. A mutation that does not compile proves nothing.
- Do not pipe `make build` into `tail -0`/`head -0`: the closed pipe kills `make` before it compiles and leaves a stale binary.
- **Routing check** (`internal/checks/routing.go`, client in `internal/ripestat`): third-party data comes only through `Deps.RIPE`, built from `safehttp` in the CLI and `nil` with `--no-routing`. Only public addresses are sent (`safenet.IsPublic`), at most `MaxRoutingAddresses`; every ASN/prefix/IP is validated before entering a URL; text from RIPEstat is copied to a report only after validation (country codes: two upper-case letters; MaxMind answers `?` for anycast). An incomplete run never gives `pass`. Oracles: Team Cymru (`origin.asn.cymru.com`) for origin and `valid/invalid.rpki.isbgpsafeyet.com` for RPKI. Never test with TEST-NET addresses (`203.0.113.0/24`, etc.): they are non-public, so the check correctly never sends them.
- **Report catalog** (`internal/catalog`, Portuguese in `pt.go`, English in `en.go`): every finding ID and every check ID needs an entry (title, why, fix with `{{domain}}`, verify command). `catalog_test.go` scans the string literals of `internal/checks/*.go` with `go/parser` plus `checks.Default()`, so adding an ID without an entry, or leaving an entry for a removed ID, fails the build. `Render` only pastes a plain host name into the text (anything else becomes `<domínio>`), because the text ends up in commands the reader copies. Entries describe evidence and never say "compliant" (tested). The engine reports a skipped/slow/panicking check under the check's own ID, hence the generated "check not completed" entries.
- **Sources in the catalog** (`internal/catalog/sources.go`): every explicit entry cites at least one source with a **verbatim quote**; the section number of an RFC reference is computed from the RFC text (never typed from memory) and `make check-sources` (`NIS2_CHECK_SOURCES=1`, `NIS2_RFC_DIR` optional) verifies quote and section. Non-RFC quotes are `Manual: true` and must be verified against the official legal text before adding. Legal framing (`legal` map) is attached only where an official provision names the subject (note that the letter differs between NIS2 Art. 21(2)(h) and Decreto-Lei 125/2025 Art. 27(1)(g)). A Regulation 2024/2690 reference must state that it applies only to covered entities (tested). Non-binding ENISA guidance goes in `Guidance`.
- **Score and report** (`internal/score`, `internal/report/markdown.go`): one 0–100 note per area, no global note, `nil` (`n/d`) when nothing reached a verdict; never "compliant". Network-derived text only passes through `inline` / `codeBlock` (control characters removed, truncated, fence longer than any backtick run). Tests parse the output like CommonMark.
- **Certificate lifetime** (`transport.cert.lifetime`) follows the CA/Browser Forum schedule by issue date (398 days until 2026-03-14, 200 until 2027-03-14, 100 until 2029-03-14, 47 after). Update `publicLifetimeSchedule` and its test when the Baseline Requirements change.
- **Test keys and key tag:** `dns.RRSIG.Sign` refuses a DNSKEY whose key tag is 0 (`dns: bad key`). Always build test keys via `dnssectest.newKey` (which retries on tag 0). `Verify` compares tags on both sides and the validator tries every key sharing a tag (`TestVerifyAnyTriesEveryKeyWithTheSameTag`).
- **Two languages (`pt`, `en`):** `internal/catalog/pt.go` and `en.go` mirror each other entry by entry. Tests compare them (same IDs, examples, verify commands, sources, legal framing; English text must not contain Portuguese words or claim compliance). `Source.RefEN` is the English wording of a non-neutral reference; quotations of law stay in the original language. Report UI strings live in `uiTexts` (`internal/report/markdown.go`): add new languages to both `uiTexts` and the catalog together.
- **Monitoring** (`internal/watch`, `internal/ntfy`, `cmd/nis2-pulse/watch.go`): never put the ntfy URL in an argument, log line, or error (tests leak-check `String`, `%v`, `%#v`, and every error path); never put text from the network into a notification; save state only after delivery. The scan core is `app.collect`, shared with `scan`. When mutation-testing loops, run tests with `timeout` and a terminating fake, and never `pkill -f` a pattern that appears in your own command line.
- **Legal sources drift:** `catalog.SourcesCheckedAt` records when legal/guidance quotes were last verified; the report prints it and warns after 180 days. When re-checking regulatory PDFs (e.g. CNCS Regulation 756/2026), read the document structure (annexes, levels) before searching terms, as table text in PDFs may be hyphenated or glued.
